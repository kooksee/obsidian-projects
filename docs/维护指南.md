# Obsidian Projects 维护指南（中文）

> 适用场景：你准备接手并长期维护 `pprojects`，包括日常修复、功能迭代、发布与社区协作。

## 1. 项目现状与目标

- 插件 ID：`pprojects`
- 当前版本：`1.17.4`（见 `manifest.json` 与 `package.json`）
- 技术栈：TypeScript + Svelte + esbuild + Jest + ESLint
- 上游状态：原作者已在 2025 年停止维护（`README.md` 中有说明）

维护建议目标：

1. 保持插件可安装、可运行、可回归。
2. 优先修复稳定性问题，再推进功能迭代。
3. 避免破坏现有用户数据格式（frontmatter / settings schema）。

---

## 2. 快速启动（本地开发）

### 2.1 安装依赖

- Node.js 建议使用 18.x（CI 也是 18.x）
- 安装依赖：`pnpm install`

### 2.2 常用命令

- 开发构建（watch）：`pnpm dev`
- 生产构建：`pnpm build`
- 单元测试：`pnpm test`
- 代码检查：`pnpm lint`
- Svelte 类型检查：`pnpm svelte-check`
- 样式构建：`pnpm sass-build`
- 样式 watch：`pnpm sass-watch`

> 维护实践建议：本地提交前至少执行 `pnpm build && pnpm test && pnpm lint && pnpm svelte-check`。

### 2.3 在 Obsidian 中联调

标准做法是把构建产物（`build/main.js`、`build/manifest.json`、`build/styles.css`）放到 Vault 的插件目录：

`.obsidian/plugins/pprojects/`

然后在 Obsidian 中关闭并重新启用插件，验证改动。

## 3. 核心架构速览

## 3.1 入口层

- `src/main.ts`
  - 插件生命周期：`onload` / `onunload`
  - 注册侧边栏按钮、命令、设置页、主视图
  - 加载并迁移设置（`migrateSettings`）
  - 注册文件系统事件（增删改重命名）
- `src/view.ts`
  - Obsidian `ItemView` 包装层
  - 挂载 Svelte 应用 `src/ui/app/App.svelte`
  - 注册内置视图（table/board/calendar/gallery）与第三方自定义视图

## 3.2 UI 层（Svelte）

- `src/ui/app/App.svelte`
  - 选择当前项目与视图
  - 组装 `Toolbar` + `DataFrameProvider` + `View`
  - 无项目时展示 onboarding
- `src/ui/app/DataFrameProvider.svelte`
  - 根据项目的数据源类型创建具体 DataSource
  - 触发 `queryAll()` 刷新数据
  - 处理 Dataview 依赖缺失等错误展示

## 3.3 数据层

- `src/lib/datasources/`
  - 抽象基类：`index.ts` 中 `DataSource`
  - `folder` / `tag`：基于 frontmatter 的可写数据源
  - `dataview`：通过 Dataview 查询，属于只读数据源（`readonly() === true`）
  - `frontmatter`：folder/tag 的通用中间层，负责 schema 推断和记录标准化
- `src/lib/dataApi.ts`
  - 写操作入口：新增/更新记录、字段增删改、建笔记/删笔记
  - frontmatter 编解码：`src/lib/metadata`
- `src/lib/viewApi.ts`
  - 视图层调用的“写接口”，同时更新内存数据与落盘

## 3.4 状态管理层（Svelte stores）

- `src/lib/stores/settings.ts`：项目、视图、偏好设置、归档管理
- `src/lib/stores/dataframe.ts`：当前数据源与 DataFrame（字段/记录/错误）
- `src/lib/stores/api.ts`：由 fileSystem 派生 DataApi
- `src/lib/stores/fileSystem.ts`：由 Obsidian App 派生文件系统适配

## 3.5 文件系统与事件

- `src/lib/filesystem/obsidian/filesystem.ts`
  - 对 Obsidian Vault 的封装（便于测试替换）
  - 统一 `IFile`/`IFileSystem` 抽象
- `src/events.ts`
  - create/rename/delete/change 事件驱动 DataFrame 增量同步
  - Dataview 数据源采用“重新触发查询”策略

---

## 4. 设置与数据兼容性

- 设置入口：`src/settings/settings.ts`
- 当前设置版本：`version = 2`
- 迁移路径：支持 v1 -> v2 自动迁移

维护时请优先遵守：

1. **不要破坏旧设置读取**：新增字段尽量给默认值。
2. **必须提供迁移函数**：若引入 v3，需保留 v1/v2 到 v3 的路径。
3. **优先向后兼容**：避免让用户手动删除插件配置。

## 5. 发布与版本流程

## 5.1 本地版本号

- `pnpm version <x.y.z>` 会触发 `version` 脚本：
  - 更新 `manifest.json` 的 version
  - 更新 `versions.json`

相关脚本：

- `scripts/release/version-bump.mjs`
- `scripts/release/version-beta-manifest.mjs`

## 5.2 GitHub Actions

- `ci.yml`
  - push / PR 到 `main` 时执行 build/test/lint/svelte-check
  - 在 `main` 上自动产出 beta 预发布 tag：`0.0.0-<run_number>`
- `release.yml`
  - 推送 tag 时创建正式 release（草稿）

产物固定为：

- `build/main.js`
- `build/manifest.json`
- `build/styles.css`

## 6. 你会最常改的地方（维护者视角）

### 6.1 修复字段/记录异常

优先检查：

- `src/lib/datasources/frontmatter/datasource.ts`
- `src/lib/dataframe/dataframe.ts`
- `src/lib/metadata/decode.ts` 与 `encode.ts`

### 6.2 修复视图行为

优先检查：

- `src/ui/views/*`
- `src/ui/app/viewSort.ts`
- `src/lib/viewApi.ts`

### 6.3 修复 Dataview 相关问题

优先检查：

- `src/lib/datasources/dataview/datasource.ts`
- `src/ui/app/DataFrameProvider.svelte`

重点关注：Dataview API 是否可用、查询是否返回 table、字段标准化是否一致。

## 8. 已知维护风险清单

1. **Obsidian API 变化**：大版本升级可能导致 UI 或事件行为变化。
2. **Dataview 兼容性**：Dataview 升级后查询结果类型可能变化。
3. **性能边界**：大项目（大量 Markdown）下全量查询会有性能压力。
4. **Schema 推断误差**：多类型字段混用可能被降级为 string。

建议策略：

- 先修稳定性与崩溃问题。
- 对高频路径（queryAll、merge、field update）增加回归测试。
