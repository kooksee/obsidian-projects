# 接手、运行、调试、发布指南（中文）

这份文档是“新维护者上手 SOP”，按真实维护流程组织。

## 1. 接手第一天要做什么

1. Fork 仓库并保护 `main` 分支。
2. 配置 GitHub Actions 权限（允许创建 release）。
3. 跑通本地环境并确保四个检查通过：
   - `pnpm build`
   - `pnpm test`
   - `pnpm lint`
   - `pnpm svelte-check`
4. 在 README 公告当前维护状态与支持渠道。

## 2. 本地运行（开发）

## 2.1 环境要求

- Node.js 18.x（与 CI 保持一致）
- pnpm
- Obsidian 桌面端（用于联调）

## 2.2 安装与构建

1. 安装依赖：`pnpm install`
2. 启动 watch 构建：`pnpm dev`
3. 样式 watch（可选）：`pnpm sass-watch`

## 2.3 联调方式

将以下文件复制到你的 Vault 插件目录：

`.obsidian/plugins/pprojects/`

文件列表：

- `build/main.js`
- `build/manifest.json`
- `build/styles.css`

然后在 Obsidian 里禁用再启用插件，验证改动。

## 3. 日常调试建议

## 3.1 先定位“哪一层”出问题

- 插件注册/命令问题：`src/main.ts`
- 视图装配问题：`src/view.ts`、`src/ui/app/App.svelte`
- 数据读取问题：`src/lib/datasources/*`
- 数据写入问题：`src/lib/dataApi.ts`、`src/lib/viewApi.ts`
- 事件同步问题：`src/events.ts`
- 设置异常问题：`src/settings/*`、`src/lib/stores/settings.ts`

## 3.2 常见问题速查

### Dataview 项目不显示

- 检查 Dataview 插件是否启用
- 检查查询是否返回 table
- 检查 `DataFrameProvider.svelte` 错误提示

### 字段更新后未持久化

- 检查 `ViewApi` 是否调用对应写入方法
- 检查 `DataApi` 的 frontmatter 编码是否成功
- 检查文件是否被正确匹配到当前数据源（`includes(path)`）

### 大项目卡顿

- 调低项目范围（folder/tag/dataview query）
- 调整 `projectSizeLimit`
- 优先关闭不必要视图和排序筛选

## 4. 发布流程（维护版）

## 4.1 Beta 发布（自动）

触发条件：推送到 `main`。

CI 会执行：

1. build / test / lint / svelte-check
2. 生成 `manifest-beta.json`
3. 用 `0.0.0-<run_number>` 创建 prerelease

## 4.2 正式发布（tag 驱动）

1. 更新版本号（`pnpm version x.y.z`）
2. 推送 tag
3. `release.yml` 自动构建并创建 draft release
4. 检查产物后发布

## 4.3 发布前检查清单

- [ ] 所有检查通过
- [ ] `manifest.json` 与 `versions.json` 版本一致
- [ ] 关键回归场景验证通过（至少 folder + tag + dataview 各一例）
- [ ] README / CHANGELOG 更新

## 5. 建议分支策略

- `main`：稳定分支（可发布）
- `fix/*`：缺陷修复
- `feat/*`：功能开发
- `chore/*`：构建与文档

PR 合并建议：

- 优先 squash merge，保持历史简洁
- 每个 PR 对应一个问题与一组测试结论

## 6. 建议里程碑（你接手后的 30 天）

- 第 1 周：跑通流程 + 修复高频 bug
- 第 2 周：完善文档与发布节奏
- 第 3 周：做一轮性能优化（查询与事件）
- 第 4 周：整理 roadmap 与社区协作规范
