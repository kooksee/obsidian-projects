# 项目管理功能规划与优化清单（v1 草案）

> 目标：在保持 `pprojects` 稳定性的前提下，新增更完整的“项目管理”能力，并给出可落地的优化路线。

---

## 1. 背景与目标

当前插件已经具备：项目来源管理（folder/tag/dataview）、多视图（Table/Board/Calendar/Gallery）、模板建笔记。

下一阶段建议从“可用”升级到“可管理”：

1. **项目治理能力**：状态、里程碑、负责人、优先级等标准化字段与操作。
2. **执行闭环能力**：从计划到跟踪再到复盘，有明确入口与反馈。
3. **规模化能力**：在中大型 Vault 下保持性能、稳定性与可维护性。

---

## 2. 建议新增功能（按优先级）

## P0（先做，直接提升体验）

### 2.1 项目模板中心（Project Blueprint）

**价值**：快速创建“规范化项目”。

建议内容：
- 预置模板：任务管理、内容发布、产品研发、读书计划。
- 模板包含：默认字段、默认视图、默认筛选/排序、默认新建笔记模板。

建议落点：
- `src/settings/*`（模板结构与持久化）
- `src/ui/modals/createProjectModal.ts`（创建时选择模板）
- `src/lib/stores/settings.ts`（应用模板）

### 2.2 项目健康度面板（Health Summary）

**价值**：一眼看出项目风险与推进情况。

建议指标：
- 任务总数 / 完成数 / 逾期数
- 本周新增与完成趋势
- 无负责人任务数

建议落点：
- `src/lib/dataframe/dataframe.ts`（聚合统计）
- `src/ui/app/toolbar/*` 或新增 `src/ui/app/summary/*`

### 2.3 快速操作（Quick Actions）

**价值**：降低高频操作成本。

建议能力：
- 一键新建任务（带默认字段）
- 一键归档完成项
- 一键切换“我的任务 / 全部任务 / 本周任务”

建议落点：
- `src/ui/app/toolbar/Toolbar.svelte`
- `src/lib/viewApi.ts`、`src/lib/dataApi.ts`

## 2.9 你提到的需求域：逐项分析与落地建议

你提到的场景：项目需求管理、项目任务管理、产品管理、产品功能单元管理、表格分组管理、版本管理、按 Sprint 的 todoList。

建议统一为一个层级模型，避免后续字段和视图碎片化：

- **产品（Product）**
   - 包含多个版本（Release）
- **版本（Release）**
   - 包含多个 Sprint
- **Sprint**
   - 包含需求（Requirement）与任务（Task）
- **需求（Requirement）**
   - 拆分为功能单元（Feature Unit）
- **功能单元（Feature Unit）**
   - 拆分为可执行任务（Task）

### A. 项目需求管理（Requirement）

目标：把“想法/需求”与“执行任务”分离，先做需求池，再进入开发。

建议字段：
- `type: requirement`
- `product`, `release`, `sprint`
- `priority`（P0/P1/P2）
- `status`（idea/analysis/approved/rejected）
- `owner`

建议视图：
- 需求池表格（按优先级、状态分组）
- 需求看板（analysis -> approved）

### B. 项目任务管理（Task）

目标：承接需求落地执行，支持“可跟踪的交付”。

建议字段：
- `type: task`
- `requirementId`, `featureUnitId`
- `estimate`, `actual`
- `status`（todo/doing/done/blocked）
- `assignee`, `due`

建议视图：
- Sprint 看板（todo/doing/done）
- 本周任务表（按 owner + due）

### C. 产品管理（Product）

目标：支持多产品并行，避免所有任务混在一个项目里。

建议字段：
- `type: product`
- `productCode`, `productOwner`
- `lifecycle`（incubating/growing/stable/deprecated）

建议：
- 在项目模板中预置“单产品项目模板”和“多产品组合模板”。

### D. 产品功能单元管理（Feature Unit）

目标：作为需求与任务之间的中间层，便于拆解和验收。

建议字段：
- `type: feature`
- `requirementId`
- `acceptanceCriteria`（验收标准）
- `impactScope`（影响范围）

建议视图：
- 功能单元树状/分组表（按 requirement 分组）

### E. 表格分组管理（Table Grouping）

目标：让管理者从“单条记录”视角切换到“分组视角”。

建议优先支持的分组维度：
- `status`
- `owner`
- `sprint`
- `release`
- `priority`

实现建议：
- 在 `Table` 视图增加“分组字段 + 折叠组 + 组汇总（count）”。

### F. 版本管理（Release）

目标：让交付物归属到版本，支持发布节奏管理。

建议字段：
- `type: release`
- `releaseVersion`（如 `1.3.0`）
- `releaseDate`
- `releaseStatus`（planning/developing/frozen/released）

建议视图：
- 版本时间线（Calendar）
- 版本燃尽表（任务完成趋势）

### G. Sprint todoList

目标：形成每个 Sprint 可执行的承诺清单。

建议字段：
- `sprint`
- `sprintGoal`
- `storyPoint`
- `isCommitted`（是否纳入本 Sprint 承诺）

建议能力：
- 一键筛出当前 Sprint todo
- 一键从需求池拉入 Sprint
- Sprint 结束归档与复盘导出

## 2.10 MVP 建议（先跑起来）

首版不建议一次做全，建议先实现最小闭环：

1. 字段层：`type/product/release/sprint/priority/status/owner`
2. 视图层：
    - 需求池表格（分组：priority/status）
    - Sprint 看板（todo/doing/done）
3. 操作层：
    - 从需求转任务（复制关键字段）
    - 任务关联需求（`requirementId`）
4. 输出层：
    - 当前 Sprint todoList 导出 Markdown

只要这个闭环跑通，你的“项目 + 产品 + 版本 + Sprint”管理就已经能投入日常使用。

## 3. 需要优先优化的地方（代码级）

## 3.1 查询与刷新链路（性能优先）

问题：项目切换、文件事件触发时，存在重复全量查询风险。

优化建议：
- 在 `src/ui/app/DataFrameProvider.svelte` 增加去抖与并发保护（同一时刻仅一个查询）。
- 对 Dataview 数据源增加“低频刷新模式”（自动/手动）。
- 在 `src/events.ts` 对高频文件事件做批量合并（batch）后刷新。

## 3.2 settings store 复杂度（可维护性优先）

问题：`src/lib/stores/settings.ts` 逻辑集中、职责多，后续功能扩展会放大维护成本。

优化建议：
- 拆分为 `projectActions` / `viewActions` / `archiveActions`。
- 为关键操作补充单测（重复项目、重复视图、归档恢复边界）。

## 3.3 数据写入批处理（稳定性优先）

问题：连续字段更新可能导致多次重复写盘。

优化建议：
- 在 `src/lib/dataApi.ts` 增加同文件写入合并队列。
- 对 `encode/decode` 热点路径补充基准测试。

## 3.4 视图大数据量渲染（体验优先）

问题：表格/看板在高数据量下可能卡顿。

优化建议：
- 引入虚拟滚动或分页策略（先 Table，再 Board）。
- 对排序/过滤结果做缓存，减少重复计算。

## 3.5 可观测性（排障优先）

问题：线上问题难快速定位。

优化建议：
- 增加 debug 开关（默认关闭）。
- 记录关键耗时：`queryAll`、`merge`、`updateRecord`。

## 4. 实施路线（建议 3 个迭代）

## 迭代 A（1~2 周）

- 项目模板中心（P0）
- 快速操作（P0）
- DataFrameProvider 查询去抖与并发保护（优化）

验收标准：
- 新建项目可选模板
- 常用操作可在 2 次点击内完成
- 大量文件更新时无明显卡顿恶化

## 迭代 B（1~2 周）

- 项目健康度面板（P0）
- 里程碑管理（P1）
- settings store 拆分（优化）

验收标准：
- 可展示项目健康核心指标
- 支持按里程碑分组与筛选
- settings 相关回归测试通过

## 迭代 C（1~2 周）

- 依赖关系与阻塞标记（P1）
- 周报导出（P1）
- 写入批处理 + 视图性能优化第一版（优化）

验收标准：
- 可识别并展示阻塞项
- 一键导出周报可用
- 大项目场景下交互延迟可控

---

## 5. 风险与约束

1. **数据兼容性**：新增字段需保持 frontmatter 向后兼容。
2. **设置版本升级**：若 schema 变化，需新增版本与迁移函数（`src/settings/settings.ts`）。
3. **Dataview 差异**：Dataview 返回结构变化要有兜底。
4. **移动端差异**：性能策略需至少做桌面 + 移动端一次验证。
